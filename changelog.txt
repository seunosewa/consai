2025-10-17

- ConsAI: Rename 'claude' to 'sonnet' and add 'haiku' model
  - Backend `consai.py`:
    - Renamed model key 'claude' to 'sonnet' (still uses anthropic/claude-sonnet-4.5)
    - Added 'haiku' model: anthropic/claude-4.5-haiku with reasoning tokens: 32768

    - Use /sonnet to address Claude Sonnet 4.5
    - Use /haiku to address Claude Haiku 4.5

- ConsAI: Add Gemini CLI integration with automatic context injection
  - Backend `consai.py`:
    - Added `_format_context_for_gemini()` method to format recent conversation history (last 5 messages by default) as context
    - Updated system prompt with detailed Gemini CLI usage instructions including heredoc syntax for context-aware queries
    - Added `/gemini <query>` command that automatically includes conversation context when calling Gemini CLI
    - Gemini responses are added to conversation history so other models can reference them
    - All Gemini calls use `NODE_NO_WARNINGS=1` environment variable to suppress Node.js deprecation warnings
  - Features:
    - Models can call Gemini via executeshell for web search, fact-checking, and real-time information
    - Supports both simple queries (`NODE_NO_WARNINGS=1 gemini "question"`) and context-aware queries (using heredoc)
    - User can directly invoke with `/gemini` command for quick web searches with auto-context
    - Output displayed in magenta color to distinguish from other tool calls
  - Use cases:
    - Verify facts and dates
    - Get current information not in training data
    - Web search results
    - Second opinions on technical decisions
    - Latest documentation or release info

Impact
- Removes the large blank gap between the tool command and its output.
- Agent responses now show at most one blank line between paragraphs (i.e., two newlines), preserving readable formatting.
- Output formatting (code/ANSI text) remains intact.

  - Impact: Assistant messages support headings, lists, tables, and fenced code blocks with syntax highlighting.

2025-08-19

- Tool Calling: Make DeepSeek parsing robust
  - Backend `webv.py`:
    - Updated regex to handle spaces, tabs, and special Unicode whitespace (`\u2581`) in DeepSeek tool tags.
    - Switched from non-greedy (`.*?`) to greedy (`.*`) matching for command arguments to correctly capture complex, multi-line shell commands.
  - Impact: Reliably captures and executes complex tool calls from DeepSeek models that were previously missed.

- Tool Calling: Execute tool calls found in AI reasoning/thoughts
  - Backend `webv.py`: The tool parsing logic now scans both the `reasoning` and `content` streams, ensuring that any valid tool call is executed, regardless of where the model places it.
  - Impact: Increases the reliability of autonomous operations, as the AI can now act on a command even if it formulates it as part of its internal monologue.

- UI: Fix final summary appearing in "thinking" box
  - Backend `webv.py`: Implemented a fallback to ensure at least one `assistant_content` event is sent if the AI provides a response, preventing cases where the final answer is only in the `reasoning` stream.
  - Frontend `webv.html`: Added a safeguard to move content from the reasoning box to the final answer box if the stream ends without any `assistant_content` events, fixing the display for the user.
  - Impact: The AI's final summary is now always displayed correctly in the main answer area, separate from its thoughts.

- Tool Calling: Enhanced debugging and simplified logic
  - Backend `webv.py`:
    - Added console logging to show the original format of any malformed tool calls that are ignored.
    - Added logging to show every valid inline tool call that is successfully parsed.
    - Removed the complex and unnecessary tool call deduplication logic.
  - Impact: Easier to debug AI tool call behavior and a simpler, more direct execution flow.

- Context: Prevent AI from echoing placeholder text
  - Backend `webv.py`: Removed the `[Your previous response used tools]` placeholder from the conversation history sent to the AI.
  - Impact: Fixes a UI bug where the AI would mimic this placeholder before making a tool call, cleaning up the chat display.

2025-08-23

- Web: Add `/lastjson` debug command and cache outgoing model payloads
  - Backend `webv.py`:
    - Add `last_json_payload` field to the `Session` dataclass to store the most recent JSON payload sent to the model.
    - Implement a new `/lastjson` command: when the POST `text` is exactly `/lastjson`, the server prints the cached JSON payload to the console and immediately returns without calling any model or modifying session history.
    - Cache the final JSON payload (`payload`) into `session.last_json_payload` immediately before each OpenRouter API request (stores a JSON-serializable copy with a fallback preview).
  - Impact: Allows quick server-side inspection of the last model request for debugging without triggering model calls or changing session state.

- Web: Remove hardcoded model names from HTML welcome message
  - Frontend `webv.html`:
    - Replaced hardcoded model commands (`/claude`, `/deepseek`, etc.) with "Loading available models..." placeholder.
    - JavaScript already dynamically fetches models from `/api/models` endpoint and updates welcome message via `updateWelcomeMessage()`.
  - Impact: Model list in welcome message now automatically reflects the `MODELS` configuration in `webv.py` without requiring HTML updates.

  - Backend `consai.py`:
    - Updated system prompt for `deepthink` and `deepchat` models to explicitly clarify the correct tool call format.
    - Added warning about NOT using `[EXECUTED: ...]` format (which is display-only) vs the correct `executeshell({"command": "..."})` format.
  - Impact: Models now generate proper executable tool calls instead of display placeholders that don't actually run commands.

- ConsAI: Remove [EXECUTED: ...] display text from tool calls
  - Backend `consai.py`:
    - Simplified `_remove_inline_tool_calls()` method to completely remove tool call syntax instead of replacing with display text.
    - Tool calls now execute cleanly without leaving "[EXECUTED: ...]" artifacts in the conversation.
  - Impact: Cleaner conversation flow - tool calls execute and show their output without extra display noise.

- ConsAI: Remove [EXECUTED: ...] references from system prompt
  - Backend `consai.py`:
    - Removed warning about `[EXECUTED: ...]` format from system prompt for `deepthink` and `deepchat` models.
    - System prompt now only shows the correct `executeshell({"command": "..."})` format without mentioning the display format.
  - Impact: Prevents models from learning about the wrong format, reducing confusion and ensuring they only use the correct executable format.

- ConsAI: Add support for wrapped inline tool call format
  - Backend `consai.py`:
    - Extended `_parse_inline_tool_calls()` to support the `<｜tool calls begin｜>...<｜tool calls end｜>` wrapper format in addition to the original `executeshell({...})` format.
    - Added regex patterns to handle both regular spaces and Unicode separator characters (▁) in tool call tags.
    - Updated `_remove_inline_tool_calls()` to clean both wrapper and original formats from displayed content.
    - Fixed linter warnings by removing unused imports (`Union`, `cast`) and unused variable (`supports_formal_tools`).
  - Impact: ConsAI now parses and executes tool calls from models that use the wrapped format, increasing compatibility with different AI providers.

- ConsAI: Add markdown parsing for shell commands
  - Backend `consai.py`:
    - Added a fallback to `_parse_inline_tool_calls` to recognize and parse shell commands embedded in markdown code blocks (e.g., ```bash...```) that appear at the end of a model's response.
    - Updated `_remove_inline_tool_calls` to globally strip these markdown blocks to keep the final output clean.
  - Impact: Increases robustness by successfully executing commands even when models creatively format them as markdown, preventing silent failures.

- ConsAI: Refine markdown tool parsing logic
  - Backend `consai.py`:
    - Updated `_parse_inline_tool_calls` to only recognize a markdown command block if it is at the very end of the message and immediately preceded by a colon (e.g., `Do this:` followed by ```bash...```).
    - Refined `_remove_inline_tool_calls` to only strip the *specific* markdown block that was identified as a tool call, leaving the preceding colon intact and avoiding the removal of other potential markdown blocks in the response.
  - Impact: Prevents the model from accidentally triggering commands by using markdown for non-executable examples. The tool-call logic is now more precise and predictable.

- ConsAI: Add temporary user message reminder to prevent assistant prefixes
  - Backend `consai.py`:
    - Added injection of a temporary user message in `_call_bot` that reminds the model not to add prefixes like `<[:~ASSISTANTNAME said~:]>` to its responses.
    - The reminder message is dynamically generated with the current bot's name and appended to the message list before the API call.
    - This temporary message is not saved to the permanent conversation history.
  - Impact: Provides a recent, high-priority instruction to models to prevent them from generating unwanted prefixes, working in conjunction with the existing `_strip_said_tags` post-processing safety net.

- ConsAI: Implement persistent reminder injection for prefix violations  
  - Backend `consai.py`:
    - Modified reminder injection in `_call_bot` to persist across turns until model produces clean responses
    - Removed immediate flag reset after injecting reminder
    - Added logic to clear `needs_prefix_reminder` flag only when assistant response contains no forbidden prefixes
  - Impact: Reminders continue across multiple turns until violation stops, improving training effectiveness while reducing unnecessary reminders after compliance

- ConsAI: Fix stream cancellation to properly close HTTP requests
  - Backend `consai.py`:
    - Added `response.close()` call when `interrupt_event` is set during API response streaming
    - Previously only broke out of streaming loop, leaving HTTP request active in background
  - Impact: Ctrl+C now immediately terminates the API call instead of letting it continue consuming resources

2025-10-05

- ConsAI: Refactor to use LangChain framework
  - Created `langc_langchain.py` as refactored version using LangChain
  - Implementation details:
    - Created `ChatOpenRouter` custom chat model extending `BaseChatModel`
    - Implemented `_generate()` for non-streaming and `_stream()` for streaming
    - Converted conversation history from dicts to LangChain message types:
      - `HumanMessage` for user input
      - `AIMessage` for assistant responses
      - `SystemMessage` for system prompts
      - `ToolMessage` for tool execution results
    - All custom metadata (bot_id, usage, applypatch_failed) moved to `additional_kwargs`
    - Preserved ALL existing functionality:
      - Multi-model support (all 15 models)
      - Shell execution with PTY support
      - Security validation and approval prompts
      - Direct shell mode with `>` prefix
      - Special commands (/clear, /stats, /lastjson, /revert, /ask)
      - Bot addressing (/claude, /gemini, etc.)
      - Multi-line input (BEGIN...END)
      - Interrupt handling (Ctrl-C)
      - Terminal colors and beeps
      - Cost and token tracking
      - Inline tool call parsing (all 3 formats)
      - Applypatch with failure detection
  - Dependencies added to `requirements.txt`:
    - langchain-core>=0.3.0
    - langchain>=0.3.0
    - langchain-openai>=0.2.0
  - Documentation:
    - Created `LANGCHAIN_MIGRATION.md` with full migration guide
    - Created `LANGCHAIN_QUICK_REFERENCE.md` with code comparisons
    - Includes testing checklist and troubleshooting guide
  - Impact: Modernizes codebase with standard LangChain interfaces while maintaining 100% backward compatibility. Enables future integration with LangChain ecosystem (LangSmith, chains, agents, vector stores)
